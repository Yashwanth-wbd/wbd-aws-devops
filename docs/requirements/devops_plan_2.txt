## 0. Role, objective, and golden rules

**You are a senior AWS DevOps engineer.** Build the WBD MMM platform's infrastructure and delivery
pipeline. The application (UI + API) runs on **Amazon ECS on Fargate**; optimization and model
training run on **Amazon SageMaker**, orchestrated by **AWS Step Functions**; data engineering runs on
**Databricks on AWS** with **Delta Lake on S3**.

**Golden rules (apply to every step):**
1. **Everything is Terraform**, run from GitHub Actions via OIDC. Exceptions: the one-time state bootstrap and the first apply per account (pipeline roles don't exist yet) — run with SSO.
2. **No secrets in Git, images or Terraform variables.** Runtime secrets live in Secrets Manager / SSM.
3. **Modularize**: reusable modules in `infra/modules/`, thin stacks in `infra/environments/{dev,staging,prod}/`.
4. **Build order: bootstrap → Dev → prove it works → Staging (same code) → Prod (same code).**
5. **Validate after every step.**
6. **Naming:** `mmm-<env>-<component>` (env = `dev|stg|prd`). **Tags:** `Application, Environment, Owner, BusinessUnit, DataClassification, ManagedBy, Component` (+ `CostCenter` if WBD Finance requires it [ASK]).
7. **SageMaker jobs, Lambda and ECS tasks run inside the VPC** (private subnets, no public IP), with KMS on volumes and outputs.

`Terraform · GitHub Actions (OIDC) · ECR · ECS on Fargate (UI + API) + ALB · Route 53 · AWS WAF
(regional) · ACM · Amazon Cognito (federated to WBD IdP) · Aurora PostgreSQL (+ RDS Proxy) · S3

(Lakeflow Jobs, Unity Catalog, Delta Lake) · Amazon API Gateway (LLM gateway) · Amazon Bedrock
Guardrails · CloudWatch + CloudTrail (+ Splunk via Firehose [ASK]) · AWS Backup.`

**Prescribed stack (slide footer):** React + TypeScript · Python / FastAPI · scikit-learn / XGBoost /
LangGraph · SciPy · RDS PostgreSQL + Databricks / S3 · ECS · AWS recommended.

**Two flows (from the slides):**
- **Auto ML training (slide 1):** scheduled / manual / app-triggered refresh → EventBridge → Step Functions → Databricks Lakeflow Jobs: ingestion from S3 into the Databricks catalog → Bronze (raw) → Silver (cleansed, validated) → Gold (per-BU modeling tables, adstock & saturation) → Feature Export (plans, runs, allocations) → Step Functions publishes **immutable Parquet + metadata** to the S3 training-data bucket → **SageMaker model training** (multi-stage models) → **evaluation** (baseline → channel lift → title adjustment) → **model registration** (approved model versioned) → SageMaker Registry + S3 (approved models + response curves).
- **Optimization and explainable planning (slide 2):** planner (upload inventory, choose objective, run & compare) → DNS/WAF → ALB → ECS UI → ECS API (FastAPI + LangGraph + QA dashboard) ↔ Aurora (plans, runs, allocations). API → **Step Functions (async execution)** → **SageMaker job for optimization & decision** (Model Summarizer: channel contribution, response curves, baseline, performance metrics · Optimizer: constrained / unconstrained across BUs, titles, periods, mixed units, owned inventory · Simulation: what-if, scenario comparison, logged override), reading the **approved model (SageMaker Registry)** and **approved response curves (S3)** → **S3 outputs (full run evidence)** → **Lambda results publisher** → Aurora. API → **API Gateway** → OpenAI / Anthropic / Google models, with **Bedrock Guardrails**. Sized for **50–150 concurrent planners** in planning seasons.

**Control plane (both slides):** Data lineage & observability · Code repository · Security (RBAC, SSO/MFA) · Amazon Bedrock for GenAI capabilities · Privacy & GenAI guardrails.
**Security + network:** IAM role assumption · IAM Identity Center · KMS · Secrets Manager · Security groups · VPC routes. **Operations:** CloudWatch metrics · CloudTrail · Terraform · CI/CD.

### Step 8 — Edge & login (Route 53, WAF, ACM, Cognito)

- **ACM**: one regional certificate for the app name (no us-east-1 cert — no CloudFront).

- **cognito**: user pool per env, **federated IdP** = WBD Okta (OIDC or SAML), hosted domain (custom domain optional), app client for the UI (Auth Code + PKCE), resource server + scopes for the API, groups/claims carrying BU + role; MFA/step-up enforced at Okta; advanced security (threat protection) on in prod [ASK]. API validates Cognito JWTs; RBAC in the app + **PostgreSQL row-level security** per BU.
- **Validate:** login through Cognito → Okta + MFA; unauthenticated request to the UI is redirected; ALB rejects non-HTTPS; WAF blocks a test SQLi; one BU can't see another BU's data.

### Step 9 — Optimization engine (Step Functions + SageMaker jobs + Lambda results publisher)
- **sagemaker** (run side): execution role for optimization jobs (read `models`/response curves, read model package metadata, write `outputs`, KMS `sagemaker`/`s3`, logs, ECR pull), **VPC config** (private-app subnets + SG), KMS volume/output keys, network isolation where the job needs no AWS calls, max runtime, **model package groups per BU** (created here, filled by Step 14).
- **step-functions** `mmm-<env>-optimization` (Standard): input = run request from the API (run id used as **execution name → idempotent**); states: validate → `sagemaker:createProcessingJob.sync` (or `createTrainingJob.sync`) with the optimizer image → on success publish → on failure mark run failed; retries with backoff, timeouts, catch → SNS. Logging (ALL, KMS) + X-Ray.
- **lambda-function** `mmm-<env>-results-publisher`: in VPC, reads the run evidence from `outputs`, writes plans/runs/allocations to Aurora via RDS Proxy (IAM auth), DLQ/on-failure destination, reserved concurrency.
- **Throughput:** 50–150 planners — SageMaker instance quotas, Step Functions concurrency guard (Map/semaphore or SQS buffer) [ASK]; **warm pools** for repeated runs [ASM].
- **⚠ What-if latency note [ASK]:** a SageMaker processing/training job typically needs minutes to start, which cannot meet a ~10 s what-if target. Options to confirm with the architect: (a) Simulation on a **SageMaker real-time or serverless endpoint** (`sagemaker.runtime`), (b) Simulation computed **in the API** from cached response curves, (c) accept async what-if. Optimization runs (minutes) stay as jobs.
- **Validate:** API starts an execution with a seed model; the job runs in the VPC; evidence lands in `outputs`; the publisher writes the run to Aurora; a failed job marks the run failed and alerts; the same run id twice starts one execution.

- **Alarms:** ALB 5xx > 2 %, API no healthy targets, availability < 99.5 % (business hours), **Step Functions** executions failed / timed out / throttled, **optimization runtime** (standard > 2 min, large > 10 min), **SageMaker job failures**, **Lambda publisher** errors + DLQ not empty, **Aurora** CPU > 80 %, connections > 80 %, free storage, replica lag, cert expiry < 30 d, budget, ECS deployment rolled back, GuardDuty High, break-glass sign-in (prod), **training pipeline failed / data stale**, **model drift / failed thresholds** (from Step 14), Release 2: LLM gateway 4xx/5xx/latency, guardrail interventions, token quota.
- **Logs:** ECS, Lambda, Step Functions, SageMaker, WAF, ALB → CloudWatch (retention 30 dev / 90 stg / 90+ prd) → Firehose → Splunk [ASK]; data-protection policy on log groups.
- **Validate:** a test alarm reaches on-call; one `run_id` is traceable API → Step Functions → SageMaker → Lambda → Aurora.

### Step 11 — Backup & DR

## 8. Security, authorization & OIDC

- Keyless CI/CD (GitHub OIDC → per-env roles bound to `repo:<org>/<repo>:environment:<env>`).
- Engineers: IAM Identity Center + permission sets. **App users: Cognito federated to WBD Okta (MFA, step-up for approvals/overrides) → app RBAC → PostgreSQL RLS per BU.**
- Workloads: per-service ECS task roles, per-job SageMaker execution roles, per-state-machine roles, Lambda role — all with the permission boundary.
- Encryption: KMS everywhere (incl. SageMaker volumes/outputs/artifacts); TLS 1.2+ (ALB, Aurora `force_ssl`, API Gateway). WORM for approved scenarios and training data.
- Pipeline gates: SAST, dependency scan, secret scan, Trivy image scan + SBOM, Checkov, DAST before prod.
- Edge: **regional WAF on the ALB** + rate limits; Shield Standard (Advanced if WBD requires).
- GenAI: external provider calls only through the gateway, guardrails on every call, no WBD data to providers without written approval.

## 9. Deployment strategy & rollback

- ECS (UI, API): rolling update + circuit breaker; blue/green optional.
- Optimization engine: new optimizer image = new SSM image tag; rollback = previous tag (no in-flight execution affected).
- Models: promotion = approve model package; rollback = re-approve the previous version / reject current.
- Data jobs: Databricks bundle redeploy of the previous `data-v*` tag.
- DB: Alembic migrations as a one-off ECS task before the new API; expand-then-contract; Aurora snapshot before prod migration.
- Infra: revert PR + apply. GenAI: flag off. **Practise every rollback in staging.**
