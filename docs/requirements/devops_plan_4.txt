## 0. Role, objective, and golden rules

**You are a senior AWS DevOps engineer.** Change the built v3 WBD MMM platform to the v4 architecture.
The application (UI + API) **and the inference & optimization engine** run on **Amazon ECS on Fargate**;
model training, evaluation and the registry stay on **Amazon SageMaker**; everything is orchestrated by
**AWS Step Functions**; optimization requests are **buffered in Amazon SQS** and dispatched by a
**Lambda**; data engineering runs on **AWS Glue** with **Delta Lake on S3**, fed by an **export from the WBD
Databricks source catalog**; planners sign in with **WBD Okta**.

**Golden rules (apply to every step):**
1. **Everything is Terraform**, run from GitHub Actions via OIDC. Exceptions: the one-time state bootstrap and the first apply per account — run with SSO.
2. **No secrets in Git, images or Terraform variables.** Runtime secrets live in Secrets Manager / SSM (v4 adds the Databricks export service-principal secret and the Glue DB user).
3. **Modularize**: reusable modules in `infra/modules/`, thin stacks in `infra/environments/{dev,staging,prod}/`; edit dev, then `scripts/sync-environments.ps1`.
4. **Build order: dev → prove it works → staging (same code) → prod (same code).**
5. **Validate after every step.**
6. **Naming:** `mmm-<env>-<component>` (env = `dev|stg|prd`). **Tags:** `Application, Environment, Owner, BusinessUnit, DataClassification, ManagedBy, Component`.
7. **ECS tasks, Glue jobs, SageMaker jobs and Lambda functions run inside the VPC** (private subnets, no public IP), with KMS on volumes, queues, job bookmarks, logs and outputs.
8. **Remove what v4 drops** (Databricks Lakeflow + write-back, EventBridge connection, SageMaker optimization job, `databricks.yml`) – no leftover modules, variables, outputs, docs or runbooks.

- **step-functions `mmm-<env>-optimization`:** `ApplyDefaults` → `GetOptimizerTaskDefinition` (SSM) → **`RunOptimizer` = `arn:aws:states:::ecs:runTask.sync`** (cluster `mmm-<env>`, launch type FARGATE, private-app subnets, `tasks` SG, `assignPublicIp = DISABLED`, container overrides `RUN_ID`, `BUSINESS_UNIT`, `RUN_TYPE`, `INPUT_S3_URI`, `OUTPUT_S3_URI`, `DRY_RUN`; `TimeoutSeconds = optimizer_max_runtime_seconds`; retries on `ECS.AmazonECSException` / capacity errors) → `PublishResult` / `PublishFailure` (results publisher, `live` alias). - **Alternative [ASK]:** a long-running ECS **worker service** that polls SQS and scales on queue depth (no task start-up per run, ~30–60 s saved) instead of one `RunTask` per run. Default = `RunTask.sync` per run (the slide draws Step Functions → container; isolation per run, simple cancel).
- **Remove:** SageMaker optimization run role, `createProcessingJob.sync` state, SSM `images/sagemaker-optimizer`, ECR `mmm/sagemaker-optimizer`, SageMaker Processing quota for optimization.
- **results publisher:** unchanged for runs; also handles the new `model_results` event (Step 14).

## 8. Security, authorization & OIDC (v4)

- Keyless CI/CD (GitHub OIDC → per-env roles bound to `repo:<org>/<repo>:environment:<env>`).
- Engineers: IAM Identity Center + permission sets. **App users: WBD Okta (OIDC at the ALB, MFA in Okta) → `groups` claim → app RBAC → PostgreSQL RLS per BU** (unchanged).
- Workloads: per-service ECS task roles (**+ optimizer**), dispatcher / publisher / **Databricks export** Lambda roles, **Glue role**, per-state-machine roles, SageMaker training roles — all with the permission boundary. Only the API can send to the run queue; only the dispatcher can start optimization executions; only the optimization state machine can run the optimizer task; only Glue (`mmm_etl`) and the publisher write to RDS besides the API.
- Databricks: the WBD workspace reaches our account only through the Unity Catalog role (write on `raw/databricks/*`); our Lambda reaches Databricks with a dedicated service principal (secret in Secrets Manager, rotated).
- Encryption: KMS everywhere (RDS, S3, SQS, logs, secrets, Glue bookmarks + logs, ECS ephemeral storage AWS-managed); TLS 1.2+. WORM for approved scenarios and training data. User uploads: TLS-only, per-BU key, optional malware scan.
- Pipeline gates unchanged (secret scan, SAST, Trivy, Checkov, actionlint; gaps: SBOM, DAST, cosign).

## 9. Deployment strategy & rollback (v4)

- ECS (UI, API): rolling update + circuit breaker. **Optimizer: new task-definition revision + SSM pointer; rollback = previous revision** (running tasks finish on their revision).
- Training image: SSM pointer; publisher: Lambda alias; dispatcher + Databricks export Lambda: Terraform (revert PR + apply).
- **Glue scripts:** versioned prefix `scripts/<version>/`; rollback = point the jobs back to the previous version.
- DB: Alembic migrations as a one-off task; RDS DB snapshot before prod migrations (incl. the new model-result / Gold tables).
- Models: approve / re-approve previous version. Infra: revert PR + apply. GenAI: flag off. **Practise every rollback in staging.**
