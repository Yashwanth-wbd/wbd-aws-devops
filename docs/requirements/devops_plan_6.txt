## 0. Role, objective, and golden rules

**You are a senior AWS DevOps engineer.** Change the built v5 WBD MMM platform to the v6 architecture.
The application (UI + API) and the inference & optimization engine run on **one Amazon ECS cluster on
Fargate** behind an **internal ALB** reached from the WBD network; model training, evaluation and the
registry stay on **Amazon SageMaker**; everything is orchestrated by **AWS Step Functions**; optimization
requests are **buffered in Amazon SQS**; data engineering runs on **AWS Glue** with **Delta Lake on S3** and
**lineage in the Glue Data Catalog + SageMaker**, fed by an export from the WBD Databricks source catalog;
**all writes to RDS go through the API or the results/data publisher**; planners sign in with **WBD Okta**;
the Release 2 explanation calls **Amazon Bedrock** privately with **Bedrock Guardrails**.

**Golden rules (apply to every step):**
1. **The repo's Terraform is the reference build** of `aws_resource_list_6.xlsx`; WBD Infra creates the real resources with its own IaC. Keep the list and the code in step – every change here is reflected in the list (regenerate with `tools/build_v6.py`).
2. **No secrets in Git, images or Terraform variables.** Runtime secrets live in Secrets Manager / SSM (v6 removes `llm/*` – Bedrock needs no API keys). Values supplied by WBD are marked `# add actual value`.
3. **Modularize**: reusable modules in `infra/modules/`, thin stacks in `infra/environments/{dev,staging,prod}/`; edit dev, then `scripts/sync-environments.ps1`.
4. **Build order: dev → prove it works → staging (same code) → prod (same code).**
5. **Validate after every step.**
6. **Naming:** `mmm-<env>-<component>` (env = `dev|stg|prd`). **Tags:** `Application, Environment, Owner, BusinessUnit, DataClassification, ManagedBy, Component`.
7. **No public entry** (v6): nothing inbound from the internet; the ALB is internal; public subnets only host NAT.
8. **One IAM role per integration** ("AWS IAM" on every arrow), all with the permission boundary; Bedrock access only for the API role, only for the approved model IDs, only with the MMM guardrail.
9. **Remove what v6 drops** (LLM gateway, proxy Lambda, `llm/*`, `execute-api` endpoint, `genai` SG, internet-facing ALB) – no leftover variables, outputs, docs or runbooks.

## 8. Security, authorization & OIDC (v6)

- **No public entry:** internal ALB only; SG source = WBD ranges; public subnets only for NAT.
- Keyless CI/CD for the three repositories. Engineers: **IAM Identity Center federated with Okta** + permission sets. App users: Okta OIDC at the internal ALB → `groups` → app RBAC → PostgreSQL RLS per BU.
- Workloads: one role per integration. **Only the API role may call Bedrock**, only the approved models, only with the MMM guardrail (IAM condition) and only through the `bedrock-runtime` endpoint (endpoint policy).
- Encryption: KMS on every store; `genai` key for the guardrail and invocation logs.
- Audit: CloudTrail management events (Bedrock API calls included) + S3 data events on the MMM buckets.
