# infra/environments/dev – dev account stack

The dev stack is built first and grows step by step. Staging and prod are copies of this
folder (Step 12), made by `scripts/sync-environments.ps1`. Change the code here, not there.

## What is in it so far

### Step 3 – Foundation (`main.tf`)

| Module | Creates in the dev account |
|---|---|
| `kms` | KMS keys with rotation: `rds`, `s3`, `logs`, `secrets`, `ecr`, `sagemaker`, `sqs` (+ per-BU `s3-<bu>` and `genai` when those flags are on) |
| `permission_boundary` | `mmm-dev-permission-boundary` policy |
| `iam_oidc` | GitHub OIDC provider + `mmm-dev-gha-plan`, `-gha-apply`, `-gha-deploy`, `-gha-ecr-push`, `-gha-ecr-read`, model governance roles when `enable_data_platform` |
| `budgets` | Monthly budget and cost anomaly monitor |

Dev-specific behaviour:

- `gha-ecr-push` also trusts CI builds on `main` (images are built only in dev).
- `gha-ecr-read` trusts the `staging` GitHub Environment (copy images dev → staging).
- `gha-plan` trusts pull requests (disabled in prod).

### Step 4 – Network (`main.tf`, module `network`)

| Item | dev |
|---|---|
| VPC | `mmm-dev-vpc`, `10.40.0.0/19` (placeholder) |
| AZs | 2, pinned by AZ ID |
| Subnets | public, private-app, private-data, private-endpoint × 2 AZs |
| NAT | 1 shared NAT gateway |
| Endpoints | S3/DynamoDB gateway; interface endpoints including `states`, `sqs`, `sagemaker.api` (+ `execute-api`, `bedrock-runtime` with GenAI) |
| Security groups | `endpoints`, `alb`, `api`, `ui`, `tasks`, `data_clients`, `rds_proxy`, `rds`, `sagemaker`, `lambda` (+ `genai` with Release 2) |
| Flow logs | `/aws/vpc/mmm-dev/flow-logs`, KMS `logs` key |

Subnet layout: [`modules/network/README.md`](../../modules/network/README.md).

### Step 5 – Secrets and configuration (`main.tf`, module `secrets`)

Secrets Manager (values filled **out of band**, none generated by Terraform):

| Secret | Purpose |
|---|---|
| `mmm/dev/api/db` | App DB connection JSON (after first migration) |
| `mmm/dev/rds/proxy`, `mmm/dev/rds/migrate` | DB users for RDS Proxy |
| `mmm/dev/okta/alb-client` | Okta OIDC client secret for the ALB, JSON `{"client_secret": "..."}` (WBD Okta team); read by Terraform once `okta_sign_in_enabled = true` |
| `mmm/dev/splunk/hec` | Splunk HEC token (WBD) |
| `mmm/dev/thirdparty/<vendor>` | Third-party API credentials |
| `mmm/dev/llm/<provider>` | LLM API keys when `enable_genai` |

RDS admin password: RDS-managed secret (`terraform output rds.master_user_secret_arn`).

SSM (non-secret settings): `/mmm/dev/genai_enabled`, `okta/issuer`, `optimization/max_concurrent_runs`, `databricks/host`, `genai/token_quota/<bu>`, with the data platform `databricks/export_job_ids`; release pointers `ecs/optimizer_task_definition` and `images/sagemaker-training` (`optimization.tf`). Data-platform secrets: `databricks/export-sp`, `rds/etl`.

### Step 6 – Platform (`main.tf`)

| Item | dev |
|---|---|
| ECR | `mmm/api`, `mmm/ui`, `mmm/optimizer`, `mmm/sagemaker-training` |
| Log bucket | `wbd-mmm-dev-logs-<region_code>` |
| Data buckets | `landing`, `results`, `approved-worm`, `exports`, `models`, `uploads` (CORS for the app URL, `uploads_retention_days`) (+ `training-data`, `lakehouse`, `glue-assets` with data platform) |
| RDS PostgreSQL | Instance `mmm-dev-postgres`, PostgreSQL 16.6, `db.t4g.medium` (placeholder), gp3 50 GiB autoscaling to 200, Single-AZ (Multi-AZ in staging / prod), 7-day PITR |
| RDS Proxy | `mmm-dev-postgres-proxy`; TLS + IAM auth required; `rds/proxy` and `rds/migrate` secrets (+ `rds/etl` with the data platform) |

Creating the instance and the proxy takes about 15–20 minutes on first apply.

### Step 7 – ECS and optimization (`ecs.tf`, `optimization.tf`)

| Item | dev |
|---|---|
| Cluster | `mmm-dev-ecs`, Fargate, Container Insights enhanced, ECS Exec |
| Services | **`api`** (1 vCPU / 2 GB, CPU autoscaling 1–2), **`ui`** (0.25 vCPU / 0.5 GB, 1–2) |
| ALB | HTTPS, Okta `authenticate-oidc` on the default (UI) action and `/api/*` (unauthenticated `/api/*` → 401); `/api/health` open. Until `okta_sign_in_enabled = true` every other path answers 503 |
| What-if | Synchronous in the **API** (no worker service) |
| Run queue (`run-queue.tf`) | The API sends each optimization request to SQS `mmm-dev-optimization-requests` (DLQ `-dlq`); Lambda **`mmm-dev-run-dispatcher`** starts executions while fewer than `max_concurrent_runs` (SSM `/mmm/dev/optimization/max_concurrent_runs`) are running, and drops requests older than `max_queue_wait_minutes` |
| Optimization | State machine `mmm-dev-optimization`: SSM `ecs/optimizer_task_definition` → ECS Fargate task **`mmm-dev-optimizer`** (`ecs:runTask.sync`, `optimizer_cpu` / `optimizer_memory` / `optimizer_ephemeral_storage_gib`, `optimizer` security group; `run_type` optimize / forecast) → Lambda **`mmm-dev-results-publisher`** (alias `live`) |
| Tasks | `migrate` (one-off), `platform-check` (`enable_platform_check_task`), `optimizer` (per run) |

Seed images (public Python) serve `/api/health` and `/healthz` until the first `deploy.yml` run.
Terraform ignores `task_definition` and `desired_count` on services.

### Step 8 – Front door (`frontdoor.tf`)

| Item | dev |
|---|---|
| Okta sign-in | ALB `authenticate-oidc` against `okta_issuer` with `okta_client_id`; client secret from `mmm/dev/okta/alb-client`; session cookie `mmm-session` (`session_hours`). UI `LOGOUT_URL` = Okta logout |
| ALB + WAF | Regional WAF (`waf-regional`): managed rules, rate limit, optional geo allow list; `waf_count_only` for observe mode |
| DNS | `terraform output dns_records_for_wbd` or Route 53 alias when `route53_zone_id` is set |
| Okta | `terraform output okta_app_settings` (OIDC Web app, redirect URI `<app>/oauth2/idpresponse`, sign-out URI, scopes, `groups` claim for the WBD Okta team) |

### Step 9 – Monitoring (`monitoring.tf`)

Alarms include `ui-no-healthy-targets`, `api-no-healthy-targets`, `api-5xx-rate`, `availability`,
`rds-cpu`, `rds-free-storage`, `rds-read-latency`, `rds-write-latency`, `rds-connections`,
`whatif-p95`, `optimization-runtime-max`, `optimization-standard-p95`, run queue
`runs-oldest-request`, `runs-dlq-not-empty`, `runs-dispatcher-errors`, `runs-dispatcher-throttles`,
`runs-expired-requests`, `cert-expiry-alb`, optimization state machine **failed** / **throttled**,
publisher and dispatcher **errors**, deployment/GuardDuty events, `optimizer-task-not-started`; with
the data platform `model-refresh-*`, `model-refresh-overdue`, `model-monitor-*`, `model-drift-<bu>`,
`databricks-export-errors` and the events `glue-job-failed` / `glue-data-quality-failed`, with GenAI
the gateway and token quota alarms. Dashboards `mmm-dev-platform`, `-api-ui`, `-optimization` (incl.
run queue and optimizer tasks), `-rds`, `-cost` (+ `-training` incl. drift, `-data-pipeline`, `-genai`).
Splunk when `enable_splunk_shipping = true`.

### Step 10 – Backup (`backup.tf`)

AWS Backup selects resources tagged `backup = true`: RDS instance, buckets `results`,
`approved-worm`, `models`, and with the data platform `training-data` and `lakehouse`. Dev vault
allows manual deletion of recovery points.

### Step 11 – CI/CD

Workflows: `api-ci`, `ui-ci`, `optimizer-ci`, `training-ci`, `publisher-ci`, `deploy`, `terraform`,
`repo-checks`, `glue.yml`, `model-governance.yml`. See [docs/09](../../../docs/09-cicd-pipelines.md).

| Event on `main` | Result in dev |
|---|---|
| `apps/api/**` | `api-ci` → `deploy` (migrate + `mmm-dev-api`) |
| `apps/ui/**` | `ui-ci` → `deploy` (`mmm-dev-ui`) |
| `apps/optimizer/**` | `optimizer-ci` → `deploy` registers a `mmm-dev-optimizer` revision → SSM `/mmm/dev/ecs/optimizer_task_definition` |
| `data/glue/jobs/**` | `glue` uploads the scripts to `s3://<glue-assets>/scripts/` (data platform) |
| `apps/sagemaker-training/**` | `training-ci` → SSM `sagemaker-training` |
| `apps/results-publisher/**` | `publisher-ci` → `deploy` updates Lambda code |
| `infra/**`, `data/model-thresholds.yaml` | `terraform` apply dev (staging/prod after approval) |

Outputs: `github_environment_variables`, `github_repository_variables`.

### Step 12 – Staging and prod copies

Edit `.tf` files here only, then `.\scripts\sync-environments.ps1`. Offline:
`.\scripts\mock-plan.ps1 -Environment dev` for the current plan size.

### Step 13 – Data platform (`data.tf`, flag `enable_data_platform`)

Model refresh state machine `mmm-dev-model-refresh`: Databricks export (Lambda
`mmm-dev-databricks-export`, Jobs API with the `databricks/export-sp` secret; raw Parquet to
`landing/raw/databricks/<bu>/<refresh_id>/` through the write-only UC role) → Glue
`mmm-dev-glue-bronze` → `-silver` (Data Quality ruleset `mmm-dev-silver`) → `-gold` → in parallel
`-export-training` (immutable snapshot) and `-export-rds` (RDS via the proxy as `mmm_etl`) →
SageMaker training → evaluation Processing → SageMaker Model Registry (`PendingManualApproval`) →
results publisher (`model_results`: predictions, lift and evaluation to RDS). Schedules and
on-demand `mmm.refresh` events.

Model monitor state machine `mmm-dev-model-monitor` (drift check per business unit): the same
export + Glue medallion with `purpose = monitor`, Glue `-export-monitor` (latest features) →
SageMaker Processing `drift` against `models/baseline/<bu>/` (published by
`model-governance.yml` on approval) → metric `MMM/Models` `ModelDrift` and alarm
`mmm-dev-model-drift-<bu>`; above the threshold (`data/model-thresholds.yaml`, default
`model_drift_threshold`) it sends an `mmm.refresh` event when `auto_refresh_on_drift = true`.
Schedules `mmm-dev-drift-<bu>` (`model_monitor_schedule`) only with
`enable_model_monitor_schedule = true` — keep it off until the first model is approved (no baseline before).

Glue job scripts: `.github/workflows/glue.yml` and `data/glue/jobs/` (when present); until then the
jobs have a seed script that stops with an error.

### Step 14 – GenAI (`genai.tf`, flag `enable_genai`)

`bedrock-guardrails` + `llm-gateway` (private API Gateway, proxy Lambda). API env `LLM_GATEWAY_URL`.
User flag: SSM `/mmm/dev/genai_enabled`.
