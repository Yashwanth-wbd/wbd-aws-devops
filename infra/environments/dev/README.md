# infra/environments/dev – dev account stack

The dev stack is built first and grows step by step. Staging and prod are copies of this
folder (Step 12), made by `scripts/sync-environments.ps1`. Change the code here, not there.

## What is in it so far

### Step 3 – Foundation (`main.tf`)

| Module | Creates in the dev account |
|---|---|
| `kms` | KMS keys with rotation: `rds`, `s3`, `logs`, `secrets`, `ecr`, `sagemaker` (+ per-BU `s3-<bu>` and `genai` when those flags are on) |
| `permission_boundary` | `mmm-dev-permission-boundary` policy |
| `iam_oidc` | GitHub OIDC provider + `mmm-dev-gha-plan`, `-gha-apply`, `-gha-deploy`, `-gha-ecr-push`, `-gha-ecr-read`, model governance roles when `enable_data_platform` |
| `budgets` | Monthly budget and cost anomaly monitor |

Dev-specific behaviour:

- `gha-ecr-push` also trusts CI builds on `main` (images are built only in dev).
- `gha-ecr-read` trusts the `staging` GitHub Environment (copy images dev → staging).
- `gha-plan` trusts pull requests (disabled in prod).

### Step 4 – Network (`main.tf`, module `network`)

| Item | dev |
|---|---|
| VPC | `mmm-dev-vpc`, `10.40.0.0/19` (placeholder) |
| AZs | 2, pinned by AZ ID |
| Subnets | public, private-app, private-data, private-endpoint × 2 AZs |
| NAT | 1 shared NAT gateway |
| Endpoints | S3/DynamoDB gateway; interface endpoints including `states`, `sagemaker.api` (+ `execute-api`, `bedrock-runtime` with GenAI) |
| Security groups | `endpoints`, `alb`, `api`, `ui`, `tasks`, `data_clients`, `rds_proxy`, `rds`, `sagemaker`, `lambda` (+ `genai` with Release 2) |
| Flow logs | `/aws/vpc/mmm-dev/flow-logs`, KMS `logs` key |

Subnet layout: [`modules/network/README.md`](../../modules/network/README.md).

### Step 5 – Secrets and configuration (`main.tf`, module `secrets`)

Secrets Manager (values filled **out of band**, none generated by Terraform):

| Secret | Purpose |
|---|---|
| `mmm/dev/api/db` | App DB connection JSON (after first migration) |
| `mmm/dev/rds/proxy`, `mmm/dev/rds/migrate` | DB users for RDS Proxy |
| `mmm/dev/splunk/hec` | Splunk HEC token (WBD) |
| `mmm/dev/thirdparty/<vendor>` | Third-party API credentials |
| `mmm/dev/llm/<provider>` | LLM API keys when `enable_genai` |

Aurora admin password: RDS-managed secret (`terraform output aurora.master_user_secret_arn`).

SSM (non-secret settings): `/mmm/dev/genai_enabled`, `cognito/*`, `databricks/host`, `genai/token_quota/<bu>`.

### Step 6 – Platform (`main.tf`)

| Item | dev |
|---|---|
| ECR | `mmm/api`, `mmm/ui`, `mmm/sagemaker-optimizer`, `mmm/sagemaker-training` |
| Log bucket | `wbd-mmm-dev-logs-<region_code>` |
| Data buckets | `landing`, `results`, `approved-worm`, `exports`, `models` (+ `training-data`, `lakehouse` with data platform) |
| Aurora | Cluster `mmm-dev-aurora`, PostgreSQL 16.6 Serverless v2, **0.5–4 ACU**, 1 writer, 7-day PITR |
| RDS Proxy | TLS + IAM auth required; `rds/proxy` and `rds/migrate` secrets |

Creating Aurora and the proxy takes about 15–20 minutes on first apply.

### Step 7 – ECS and optimization (`ecs.tf`, `optimization.tf`)

| Item | dev |
|---|---|
| Cluster | `mmm-dev-ecs`, Fargate, Container Insights enhanced, ECS Exec |
| Services | **`api`** (1 vCPU / 2 GB, CPU autoscaling 1–2), **`ui`** (0.25 vCPU / 0.5 GB, 1–2) |
| ALB | HTTPS, Cognito authenticate on `/api/*` and default → UI; `/api/health` open |
| What-if | Synchronous in the **API** (no worker service) |
| Optimization | State machine `mmm-dev-optimization`: SSM image → SageMaker Processing `mmm-dev-opt-<run_id>` → Lambda **`mmm-dev-results-publisher`** (alias `live`) |
| Tasks | `migrate` (one-off), `platform-check` (`enable_platform_check_task`) |

Seed images (public Python) serve `/api/health` and `/healthz` until the first `deploy.yml` run.
Terraform ignores `task_definition` and `desired_count` on services.

### Step 8 – Front door (`frontdoor.tf`)

| Item | dev |
|---|---|
| Cognito | User pool federated to WBD Okta SAML; hosted domain `cognito_domain_prefix` (default `wbd-mmm-dev`) |
| ALB + WAF | Regional WAF (`waf-regional`): managed rules, rate limit, optional geo allow list; `waf_count_only` for observe mode |
| DNS | `terraform output dns_records_for_wbd` or Route 53 alias when `route53_zone_id` is set |
| Okta | `terraform output okta_app_settings` (ACS URL + audience for the WBD Okta team) |

### Step 9 – Monitoring (`monitoring.tf`)

Alarms include `ui-no-healthy-targets`, `api-no-healthy-targets`, `api-5xx-rate`, `aurora-cpu`,
`aurora-acu-max`, `whatif-p95`, `cert-expiry-alb`, optimization state machine **failed**, publisher
**errors**, deployment/GuardDuty events. Dashboard `mmm-dev-platform`. Splunk when
`enable_splunk_shipping = true`.

### Step 10 – Backup (`backup.tf`)

AWS Backup selects resources tagged `backup = true`: Aurora cluster, buckets `results`,
`approved-worm`, `models`. Dev vault allows manual deletion of recovery points.

### Step 11 – CI/CD

Workflows: `api-ci`, `ui-ci`, `optimizer-ci`, `training-ci`, `publisher-ci`, `deploy`, `terraform`,
`repo-checks`, `databricks.yml`, `model-governance.yml`. See [docs/09](../../../docs/09-cicd-pipelines.md).

| Event on `main` | Result in dev |
|---|---|
| `apps/api/**` | `api-ci` → `deploy` (migrate + `mmm-dev-api`) |
| `apps/ui/**` | `ui-ci` → `deploy` (`mmm-dev-ui`) |
| `apps/sagemaker-optimizer/**` | `optimizer-ci` → SSM `/mmm/dev/images/sagemaker-optimizer` |
| `apps/sagemaker-training/**` | `training-ci` → SSM `sagemaker-training` |
| `apps/results-publisher/**` | `publisher-ci` → `deploy` updates Lambda code |
| `infra/**` | `terraform` apply dev (staging/prod after approval) |

Outputs: `github_environment_variables`, `github_repository_variables`.

### Step 12 – Staging and prod copies

Edit `.tf` files here only, then `.\scripts\sync-environments.ps1`. Offline:
`.\scripts\mock-plan.ps1 -Environment dev` for the current plan size.

### Step 13 – Data platform (`data.tf`, flag `enable_data_platform`)

Model refresh state machine `mmm-dev-model-refresh`: Databricks job (EventBridge connection OAuth,
secret set out of band) → SageMaker training → evaluation Processing → SageMaker Model Registry
(`PendingManualApproval`). Schedules and on-demand `mmm.refresh` events. Databricks bundles:
`.github/workflows/databricks.yml` and `data/databricks/` (when present).

### Step 14 – GenAI (`genai.tf`, flag `enable_genai`)

`bedrock-guardrails` + `llm-gateway` (private API Gateway, proxy Lambda). API env `LLM_GATEWAY_URL`.
User flag: SSM `/mmm/dev/genai_enabled`.

## Validate Step 7 (ECS, optimization, platform check)

With AWS (ACM for `app_domain_name` must be **Issued**):

```powershell
terraform plan -out=step7.tfplan
terraform apply step7.tfplan
terraform output ecs
terraform output optimization
terraform output front_door
terraform output github_environment_variables

# 1. Services steady
aws ecs describe-services --cluster mmm-dev-ecs --services mmm-dev-api mmm-dev-ui `
  --query "services[].[serviceName,status,desiredCount,runningCount,deployments[0].rolloutState]" --output table

# 2. Target groups healthy
aws elbv2 describe-target-health --target-group-arn $(aws elbv2 describe-target-groups --names mmm-dev-api-tg --query "TargetGroups[0].TargetGroupArn" --output text) `
  --query "TargetHealthDescriptions[].TargetHealth.State"
aws elbv2 describe-target-health --target-group-arn $(aws elbv2 describe-target-groups --names mmm-dev-ui-tg --query "TargetGroups[0].TargetGroupArn" --output text) `
  --query "TargetHealthDescriptions[].TargetHealth.State"

# 3. Front door: health open; UI redirects to Cognito when unauthenticated
$url = terraform output -json front_door | ConvertFrom-Json | Select-Object -ExpandProperty app_url
curl.exe -sk -o NUL -w "%{http_code}`n" "$url/api/health"                    # 200
curl.exe -sk -o NUL -w "%{http_code} %{redirect_url}`n" "$url/"              # 302 to Cognito/Okta

# 4. SageMaker image pointers (unset until first optimizer deploy)
$opt = terraform output -json optimization | ConvertFrom-Json
foreach ($p in $opt.image_parameters.PSObject.Properties.Value) {
  aws ssm get-parameter --name $p --query "Parameter.Value" --output text
}

# 5. Publisher Lambda alias
aws lambda get-alias --function-name $opt.publisher --name live

# 6. Optimization state machine (dry run – needs valid input on S3 for a real job)
$sm = $opt.state_machine_arn
aws stepfunctions describe-state-machine --state-machine-arn $sm --query status --output text
# Example start (replace bucket and run_id after uploading input under results/runs/<id>/input/):
# aws stepfunctions start-execution --state-machine-arn $sm --name "validate-$(Get-Date -Format yyyyMMddHHmmss)" `
#   --input '{"run_id":"<uuid>","business_unit":"streaming","input_s3_uri":"s3://wbd-mmm-dev-results-use1/runs/<uuid>/input/request.json"}'

# 7. Platform check task
Invoke-Expression (terraform output -raw platform_check_run_command)
Start-Sleep 60
aws logs tail /ecs/mmm-dev/platform-check --since 10m    # PLATFORM CHECK PASSED

# 8. ECS Exec (Session Manager plugin required)
$task = aws ecs list-tasks --cluster mmm-dev-ecs --service-name mmm-dev-api --query "taskArns[0]" --output text
aws ecs execute-command --cluster mmm-dev-ecs --task $task --container app --interactive --command "id"
```

### First-time DB setup

3. Set `enable_db_bootstrap = false`, apply.
