# infra/environments/dev – dev account stack

The dev stack is built first and grows step by step. Staging and prod are copies of this
folder (Step 12), made by `scripts/sync-environments.ps1`. Change the code here, not there.

### Step 7 – ECS compute (`ecs.tf`, modules `ecs-cluster`, `alb`, `ecs-service`)

| Item | dev |
|---|---|
| Cluster | `mmm-dev-ecs`: Fargate and Fargate Spot, Container Insights enhanced, ECS Exec audited and KMS-encrypted, Service Connect namespace `mmm-dev.internal` |
| Execution role | `mmm-dev-ecs-task-exec`: pulls `mmm/*`, writes `/ecs/mmm-dev/*`, reads only the injected secrets and `/mmm/dev/*` |
| ALB | `mmm-dev-alb`: HTTPS only (TLS 1.2/1.3), 403 unless `X-Origin-Verify` matches, target group `mmm-dev-api-tg` with health check `/api/health` |
| `api` service | 0.5 vCPU / 1 GB, 1–2 tasks, CPU target 60 %, behind the ALB |
| `whatif-worker` service | 1 vCPU / 2 GB, 1–2 tasks, scales on queue depth |
| `optimizer-worker` service | 2 vCPU / 4 GB, 0–3 tasks, scales from 0 on queue depth, back to 0 when the queue is empty |
| `migrate` task | Task definition only. deploy.yml runs it before each deploy (Step 11). In bootstrap mode it runs `scripts/db-bootstrap.py` |
| `platform-check` task | Task definition only (`enable_platform_check_task`). Runs `scripts/platform-check.sh` |

Task roles (`mmm-dev-task-<name>`), least privilege:

| Role | Can do |
|---|---|
| `api` | DB as `mmm_app`; **send** jobs to SQS; read `results`; read and write `exports`; **write once** to `approved-worm` (delete, retention change and governance bypass explicitly denied); read `/mmm/dev/*` |
| `whatif`, `optimizer` | DB as `mmm_app`; **receive and delete** jobs; read and write `results`; set their own task scale-in protection; read `/mmm/dev/*` |
| `migrate` | DB as `mmm_migrator` only. In bootstrap mode also as `mmm_admin`, plus writing the `rds/migrate` and `rds/proxy` secrets |
| `platform-check` | SQS round trip, and S3 under `results/platform-check/` only |

The services start with a **seed** image (`seed_image`, a public Python image): the API answers
200 on port 8080 and the workers wait. The first real deploy (Step 11) replaces the task
definitions. Terraform ignores `task_definition` and `desired_count` on the services, so a later
`terraform apply` does not undo a deploy. The seed and platform-check images are public, so they
are pulled through the NAT gateway. Real images come from ECR through the VPC endpoints.

`DATABRICKS_TOKEN` is injected into the workers only when `databricks_token_available = true`.
An empty secret would stop the task from starting, so set this after the `databricks/sp` secret is
filled.

Expected `terraform plan` for Step 7: **49 to add**:
- Cluster: 6 (log group, cluster, capacity providers, namespace, execution role and policy)
- ALB: 4 (load balancer, target group, HTTPS listener, listener rule)
- `api`: 8 (log group, role, 2 policies, task definition, service, scaling target, CPU policy)
- `whatif-worker`, `optimizer-worker`: 11 each (as `api` without the CPU policy, plus 2 step policies and 2 alarms)
- `migrate`: 5 (log group, role, 2 policies, task definition)
- `platform-check`: 4 (no ECS Exec policy)

### Step 8 – Edge (`edge.tf`, module `edge`)

| Item | dev |
|---|---|

| Grants | Frontend bucket policy: `s3:GetObject` for this distribution only. S3 KMS key: `kms:Decrypt` for CloudFront distributions of this account |
